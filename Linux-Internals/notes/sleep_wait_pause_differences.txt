============================================================
sleep(), wait(), pause() – COMPLETE & CONFUSION-FREE NOTES
(Single-threaded and Multi-threaded C/C++)
============================================================

------------------------------------------------------------
0. Big Picture (Very Important)
------------------------------------------------------------
These functions are often confused because they all "block".
But they block for VERY DIFFERENT REASONS:

- sleep()  -> time-based blocking
- wait()   -> child-process synchronization
- pause()  -> signal-based blocking

They solve DIFFERENT problems and are NOT interchangeable.

------------------------------------------------------------
1. sleep()
------------------------------------------------------------
Purpose:
- Suspend the CALLING THREAD for a specified duration.
- Time-based blocking.

Prototype:
- unsigned int sleep(unsigned int seconds);

Header:
- <unistd.h>

Behavior:
- Returns 0 if full sleep completed.
- Returns remaining seconds if interrupted by a signal.

Single-threaded program:
- Only one thread exists → whole process effectively sleeps.

Multi-threaded program:
- ONLY the calling thread sleeps.
- Other threads continue executing normally.

Example:
------------------------------------------------------------
    sleep(5);   // calling thread sleeps for 5 seconds
------------------------------------------------------------

Signal interaction:
- If a signal arrives and a handler runs,
  sleep() returns early.

Important notes:
- sleep() does NOT wait for signals.
- sleep() does NOT synchronize threads or processes.
- sleep() is NOT precise for timing (signals may interrupt).

Interview one-liner:
- "sleep() suspends the calling thread for N seconds."

------------------------------------------------------------
2. wait() / waitpid()
------------------------------------------------------------
Purpose:
- Parent process waits for CHILD PROCESS termination.
- Process synchronization (NOT thread synchronization).

Prototype:
- pid_t wait(int *status);
- pid_t waitpid(pid_t pid, int *status, int options);

Header:
- <sys/wait.h>

Behavior:
- Blocks until a child exits.
- Returns child PID.
- Fills exit status.

Single-threaded program:
- Parent process blocks until child terminates.

Multi-threaded program:
- Only the CALLING THREAD blocks.
- Other threads in parent process continue running.

Example:
------------------------------------------------------------
    if (fork() == 0) {
        _exit(0);   // child
    } else {
        int status;
        wait(&status);  // parent waits for child
    }
------------------------------------------------------------

Signal interaction:
- If a signal interrupts wait(), it may return early
  with errno = EINTR (unless SA_RESTART is used).

Important notes:
- wait() has NOTHING to do with sleep or signals directly.
- wait() is for PROCESS lifecycle management.
- No child → wait() fails.

Interview one-liner:
- "wait() blocks until a child process terminates."

------------------------------------------------------------
3. pause()
------------------------------------------------------------
Purpose:
- Suspend the CALLING THREAD until ANY signal is delivered.
- Signal-based blocking.

Prototype:
- int pause(void);

Header:
- <unistd.h>

Behavior:
- Blocks indefinitely.
- Returns only when a signal handler runs.
- Always returns -1 with errno = EINTR.

Single-threaded program:
- Entire process waits for a signal.

Multi-threaded program:
- ONLY the calling thread pauses.
- Other threads continue running.

Example:
------------------------------------------------------------
    void handler(int) {}

    signal(SIGINT, handler);
    pause();   // waits until SIGINT (or any signal) arrives
------------------------------------------------------------

Signal interaction:
- pause() RETURNS AFTER the signal handler finishes.
- pause() does NOT consume the signal itself.

Important notes:
- pause() has NO timeout.
- pause() is commonly replaced by sigwait() in MT programs.

Interview one-liner:
- "pause() blocks the calling thread until a signal arrives."

------------------------------------------------------------
4. sleep() vs pause() vs wait() (Side-by-Side)
------------------------------------------------------------

sleep():
- Reason to block: TIME
- Unblocks when: time expires or signal interrupts
- Used for: delays

pause():
- Reason to block: SIGNAL
- Unblocks when: signal handler executes
- Used for: waiting for signals

wait():
- Reason to block: CHILD PROCESS
- Unblocks when: child terminates
- Used for: process synchronization

------------------------------------------------------------
5. Single-thread vs Multi-thread (Mental Model)
------------------------------------------------------------

Single-threaded program:
- sleep()  -> whole process sleeps
- pause()  -> whole process waits for signal
- wait()   -> process waits for child exit

Multi-threaded program:
- sleep()  -> only calling thread sleeps
- pause()  -> only calling thread waits for signal
- wait()   -> only calling thread waits for child
- Other threads continue normally

KEY RULE:
- Blocking calls ALWAYS block the calling thread, not the process.

------------------------------------------------------------
6. Common Confusions (Cleared)
------------------------------------------------------------

❌ "pause() is like sleep()"
✔ No. pause() waits for SIGNAL, sleep() waits for TIME.

❌ "wait() is for threads"
✔ No. wait() is for CHILD PROCESSES only.

❌ "sleep() waits for signals"
✔ No. sleep() is time-based; signals only interrupt it.

❌ "pause() handles the signal"
✔ No. pause() just waits; handler handles the signal.

------------------------------------------------------------
7. Where sigwait() Fits (Important)
------------------------------------------------------------
- sigwait() is a BETTER alternative to pause() in MT programs.
- sigwait() synchronously receives signals.
- Avoids async signal handlers.

pause():
- async
- handler-based
- unsafe in MT programs

sigwait():
- synchronous
- thread-controlled
- preferred in MT programs

------------------------------------------------------------
8. Interview One-Liners (Memorize)
------------------------------------------------------------
- sleep()  → "Time-based suspension of calling thread"
- wait()   → "Parent waits for child process termination"
- pause()  → "Thread waits until a signal arrives"
- sigwait()→ "Thread synchronously waits for a signal"

------------------------------------------------------------
9. Modern High-Resolution Timing: nanosleep() & clock_nanosleep()
------------------------------------------------------------
Limitations of sleep():
- Resolution is only in whole seconds.
- May be implemented using SIGALRM on older POSIX systems, interfering with alarms.

Modern POSIX Alternative:
- int nanosleep(const struct timespec *req, struct timespec *rem);
- int clock_nanosleep(clockid_t clock_id, int flags, const struct timespec *req, struct timespec *rem);
- Nanosecond resolution.
- Guaranteed independent of signals like SIGALRM.
- If interrupted by a signal, stores remaining un-slept time in *rem.
- C++11 std::this_thread::sleep_for() / sleep_until() is built on these primitives.

------------------------------------------------------------
10. waitpid() Options & Status Inspection Macros
------------------------------------------------------------
Prototype: pid_t waitpid(pid_t pid, int *status, int options);

Meaning of the 'pid' Argument:
- pid > 0: Wait for the specific child whose process ID equals 'pid'.
- pid == -1: Wait for ANY child process (identical behavior to wait()).
- pid == 0: Wait for any child process whose process group ID (PGID) equals
  that of the calling parent process.
- pid < -1: Wait for any child process whose PGID equals |pid| (absolute value).

Return Values:
- > 0: PID of the child that changed state / terminated.
- == 0: Returned only when WNOHANG is set and children exist, but none
  have changed state yet.
- == -1: Error. errno = ECHILD (no unreaped children exist), or errno = EINTR.

Options flags:
- WNOHANG: Return immediately if no child has terminated (non-blocking).
- WUNTRACED: Return if a child stopped (e.g. via SIGSTOP / SIGTSTP).
- WCONTINUED: Return if a stopped child was resumed via SIGCONT.

Status Inspection Macros (MUST inspect status before reading code):
- WIFEXITED(status)   : True if child terminated normally (exit() or return).
- WEXITSTATUS(status) : Returns the 8-bit exit status (0-255).
- WIFSIGNALED(status) : True if child was killed by an unhandled signal.
- WTERMSIG(status)    : Returns the signal number that killed the child.
- WCOREDUMP(status)   : True if child produced a core dump.
- WIFSTOPPED(status)  : True if child is stopped by a signal.
- WSTOPSIG(status)    : Returns the signal number that stopped the child.

11. Production SIGCHLD Reaper Loop (The Non-Blocking Pattern)
------------------------------------------------------------
Why a simple wait() inside SIGCHLD handler is a BUG:
- Standard signals (like SIGCHLD) are NOT queued.
- If 5 children terminate simultaneously, the kernel delivers only ONE SIGCHLD.
- Calling wait() once reaps only one child, leaving 4 zombies!
- Calling wait() in a loop will block when no more zombies exist, hanging the process.

The Correct Production Reaper:
    void sigchld_handler(int) {
        int saved_errno = errno;
        pid_t pid;
        int status;
        // Non-blocking loop reaps all currently terminated children:
        while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
            // Child pid reaped cleanly
        }
        errno = saved_errno;
    }

------------------------------------------------------------
12. Race Conditions: pause() vs sigsuspend()
------------------------------------------------------------
The Classic pause() Race Condition:
    // Thread wants to wait for a signal:
    // If signal arrives HERE (before pause executes),
    // the handler runs, finishes, and then:
    pause(); // Hangs forever! Missed the signal!

The Solution — sigsuspend():
- Atomically replaces the thread's signal mask AND suspends the thread.
- Eliminates the race condition between unmasking a signal and pausing.
- Prototype: int sigsuspend(const sigset_t *mask);
- In multithreaded C++, sigwait() or std::condition_variable is preferred.
