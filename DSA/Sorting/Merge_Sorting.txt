==========================================================
MERGE SORT – TIME & SPACE COMPLEXITY (STEP-BY-STEP)
==========================================================

----------------------------------------------------------
0) WHAT IS MERGE SORT?
----------------------------------------------------------
• Merge Sort is a DIVIDE-AND-CONQUER sorting algorithm
• It divides the array into two halves
• Recursively sorts each half
• Merges the two sorted halves

Key idea:
"Divide until single elements, then merge in sorted order"

----------------------------------------------------------
1) WHAT COSTS TIME IN MERGE SORT?
----------------------------------------------------------
• Dividing the array is cheap (just index calculation)
• Merging two sorted arrays of total size n costs Θ(n)

General recurrence relation:
T(n) = T(left half) + T(right half) + Θ(n)

----------------------------------------------------------
2) DIVIDE STEP (ALWAYS SAME)
----------------------------------------------------------
Split:
n → n/2 + n/2

This split happens REGARDLESS of input order.

----------------------------------------------------------
3) MERGE STEP (KEY OPERATION)
----------------------------------------------------------
Given two sorted halves:
• Compare elements one by one
• Copy smaller element to temporary array
• Continue until both halves are exhausted

Merge cost:
Θ(n)

----------------------------------------------------------
4) BEST CASE TIME COMPLEXITY
----------------------------------------------------------
Condition:
• Already sorted input

Important:
• Merge Sort does NOT take advantage of sorted input
• It still divides and merges completely

Recurrence:
T(n) = 2T(n/2) + n

Recursion tree:
Level 0:          n        → work = n
Level 1:       n/2  n/2    → work = n
Level 2:     n/4 n/4 ...   → work = n
...
Last level: 1

Number of levels:
log₂(n)

Work per level:
n

BEST CASE TIME:
O(n log n)

----------------------------------------------------------
5) AVERAGE CASE TIME COMPLEXITY
----------------------------------------------------------
• Input distribution does not matter
• Same divide + merge steps occur

AVERAGE CASE TIME:
O(n log n)

----------------------------------------------------------
6) WORST CASE TIME COMPLEXITY
----------------------------------------------------------
• Even worst input must be fully merged

WORST CASE TIME:
O(n log n)

----------------------------------------------------------
7) SPACE COMPLEXITY (VERY IMPORTANT)
----------------------------------------------------------
• Merge process uses a temporary array
• Size of temporary array = n

Extra space used:
O(n)

Recursion stack:
O(log n)

Total auxiliary space:
O(n)

----------------------------------------------------------
8) IMPORTANT CLARIFICATION
----------------------------------------------------------
Merge Sort is NOT in-place (for arrays) because:
• It requires extra memory for merging

But:
• It is STABLE (preserves order of equal elements)

----------------------------------------------------------
9) SUMMARY TABLE
----------------------------------------------------------

+----------------+----------------------+----------------------+
| Scenario       | Time Complexity      | Space Complexity     |
+----------------+----------------------+----------------------+
| Best Case      | O(n log n)           | O(n)                 |
| Average Case   | O(n log n)           | O(n)                 |
| Worst Case     | O(n log n)           | O(n)                 |
+----------------+----------------------+----------------------+

----------------------------------------------------------
10) PROPERTIES (INTERVIEW FAVORITE)
----------------------------------------------------------

+----------------------+------------------------------+
| Property             | Merge Sort                   |
+----------------------+------------------------------+
| Stable               | Yes                          |
| In-place             | No (arrays)                  |
| Comparison-based     | Yes                          |
| Worst-case guarantee | Yes                          |
| Recursion used       | Yes                          |
+----------------------+------------------------------+

----------------------------------------------------------
11) ONE-LINE INTERVIEW SUMMARY
----------------------------------------------------------
Merge Sort always divides the array into two halves and
merges them in linear time, leading to O(n log n) time in
all cases, with O(n) extra space and stable sorting.
