   File: 14_Introduction_to_classes_Readme.txt
   Priority: CRITICAL

   - Simplifies CRTP (Curiously Recurring Template Pattern)

   };

1. DEDUCING 'THIS' (EXPLICIT OBJECT PARAMETERS)
------------------------------------------------
Where: 14_Introduction_to_classes_Readme.txt

Explanation:
Before C++23, to provide const and non-const overloads of a member function,
you needed to write the same function twice:

class Widget {
    std::string data;
public:
    // Non-const overload
    std::string& getData() & { return data; }
    
    // Const overload
    const std::string& getData() const& { return data; }
    
    // Rvalue overload
    std::string&& getData() && { return std::move(data); }
};

With C++23 deducing 'this', you write it once:

class Widget {
    std::string data;
public:
    // One function handles all cases
    auto&& getData(this auto&& self) {
        return std::forward<decltype(self)>(self).data;
    }
};

Benefits:
- Eliminates code duplication
- Simplifies CRTP pattern
- Makes recursive lambdas easier
- Better const-correctness

Interview Question:
"What is deducing 'this' in C++23 and why is it useful?"

Expected Answer:
"Deducing 'this' (explicit object parameters) allows the implicit 'this'
parameter to be explicitly specified in member functions. The 'self' parameter
can be templated, allowing one function to handle const, non-const, lvalue,
and rvalue cases. This eliminates the need for multiple overloads and makes
the code more maintainable."


2. STD::PRINT AND STD::PRINTLN
-------------------------------
Where: 28_Input_and_Output_Readme.txt

Explanation:
C++23 introduces std::print and std::println as modern, type-safe alternatives
to printf and std::cout.

#include <print>

// Basic usage
std::println("Hello, World!");

// Formatted output (uses std::format syntax)
std::println("My name is {} and I'm {} years old", name, age);

// Custom formatting
std::println("Pi = {:.2f}", 3.14159);  // Pi = 3.14

// Multiple arguments
std::println("{} + {} = {}", 2, 3, 2+3);

Advantages over std::cout:
- Shorter syntax
- Better performance (no sync with C stdio)
- Type-safe (like std::format)
- Consistent formatting across platforms

Advantages over printf:
- Type-safe (compile-time checking)
- Works with user-defined types
- Modern C++ syntax


3. MULTIDIMENSIONAL OPERATOR[]
-------------------------------
Where: 21_Operator_Overloading_Readme.txt

Explanation:
Before C++23, operator[] could only take one parameter. For multi-dimensional
access, you needed chained calls or operator():

// Old way - chained operator[]
matrix[i][j] = value;  // Returns proxy object, then indexes again

// Old way - using operator()
matrix(i, j) = value;  // Works but less intuitive

C++23 allows operator[] to take multiple parameters:

class Matrix {
    std::vector<int> data;
    size_t rows, cols;
public:
    // C++23 multi-parameter operator[]
    int& operator[](size_t row, size_t col) {
        return data[row * cols + col];
    }
    
    const int& operator[](size_t row, size_t col) const {
        return data[row * cols + col];
    }
};

// Clean, natural syntax
matrix[2, 3] = 42;
int value = matrix[0, 0];


4. STD::EXPECTED<T, E>
----------------------
Where: 27_Exceptions_Readme.txt

Explanation:
std::expected is a type that represents either a successful value (T) or an
error (E). It's an alternative to exceptions for error handling.

#include <expected>

std::expected<int, std::string> divide(int a, int b) {
    if (b == 0)
        return std::unexpected("Division by zero");
    return a / b;
}

// Usage
auto result = divide(10, 2);
if (result) {
    std::println("Result: {}", *result);  // 5
} else {
    std::println("Error: {}", result.error());
}

// Or use value_or()
int value = divide(10, 0).value_or(0);

When to use std::expected vs exceptions:
- Use exceptions for truly exceptional, unrecoverable errors
- Use expected for common, recoverable errors (file not found, parse error)
- Use expected in performance-critical code (no overhead when successful)
- Use expected in noexcept code


5. STD::MDSPAN
--------------
Where: 17_Fixed-size_arrays_std_array_n_C-style_arrays_Readme.txt

Explanation:
std::mdspan is a multi-dimensional, non-owning view of contiguous data.
It's like std::span but for multiple dimensions.

#include <mdspan>

void processMatrix(std::mdspan<int, std::extents<int, 3, 4>> matrix) {
    for (size_t i = 0; i < matrix.extent(0); ++i) {
        for (size_t j = 0; j < matrix.extent(1); ++j) {
            matrix[i, j] *= 2;  // Natural syntax!
        }
    }
}

// Use with flat array
int data[12];
std::mdspan matrix(data, 3, 4);  // 3x4 matrix view
matrix[1, 2] = 42;

Benefits:
- Zero-overhead abstraction
- Natural multi-dimensional indexing
- Works with existing data (non-owning)
- Supports custom layouts and accessors
