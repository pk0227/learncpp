=================================================================
📘 C++ VIRTUAL FUNCTIONS & POLYMORPHISM
=================================================================

    🔹 1 — POINTERS/REFERENCES TO BASE CLASS
    -------------------------------------------------------------
        - Base pointer/reference can point to derived object.
        - "is-a" relationship: Derived is-a Base.

        Why Use Base Pointers?
            • Enable polymorphism (one function for all derived types).
            • Avoid dozens of overloaded functions.
            • Store different derived objects in single container.

        ⚠️ Without virtual: Base pointer calls only base functions (function hiding).
        ✅ Mark functions virtual → correct derived behavior invoked.

    🔹 2 — VIRTUAL FUNCTIONS
    -------------------------------------------------------------
        - Resolves to most-derived version when called via pointer/ref.

        virtual void func();  // Base class

        Override Requirements:
            • Same signature (name, parameters, const).
            • Same return type (except covariant).

        ✅ Implicitly virtual in derived classes (if base is virtual).
        ⚠️ Signature mismatch → not an override (compiles but won't resolve correctly).

        Calling Directly on Object:
            • Always invokes function of that object's type (no virtual resolution).

        Polymorphism:
            Compile-time: Function overload, template resolution.
            Runtime: Virtual function resolution.

        ⚠️ Don't Call Virtual from Constructors/Destructors:
            • Derived portion not yet created (ctor) or already destroyed (dtor).
            • Always resolves to Base version.

        Downside:
            • Slower (vtable lookup).
            • Extra pointer per object (vtable pointer).

    🔹 3 — OVERRIDE & FINAL
    -------------------------------------------------------------
        override Specifier:
            void func() override;  // Enforces it's an override

            • Compiler error if not overriding.
            • No performance penalty.
            • Implies virtual (no need for virtual keyword).

        ✅ Use virtual in base, override in derived (not both).

        final Specifier:
            void func() final override;  // Can't override further
            class Derived final : public Base {};  // Can't inherit

        Covariant Return Types:
            • Override can return pointer/ref to derived class.
            • Base returns Base*, Derived returns Derived*.
            • Uses actual function's return type (not dynamically adjusted).

    🔹 4 — VIRTUAL DESTRUCTORS
    -------------------------------------------------------------
        ✅ Always make destructors virtual if dealing with inheritance.

        virtual ~Base() = default;  // Virtual default destructor

        ❌ Virtual Assignment (Not Recommended):
            • Opens many issues.

        Ignoring Virtualization:
            base.Base::func();  // Call base version explicitly

        Should All Destructors Be Virtual?
            • Performance penalty (vtable pointer).

            Conventional Wisdom:
                • Public + virtual destructor (if base class).
                • Protected + non-virtual destructor (prevents deletion via base pointer).

            Modern Approach (C++11+):
                • Intended for inheritance → virtual + public.
                • NOT intended → mark class final.

    🔹 5 — EARLY VS LATE BINDING
    -------------------------------------------------------------
        Binding: Associating function call with definition.
        Dispatching: Actually invoking bound function.

        Early Binding (Static):
            • Resolved at compile-time.
            • Direct function calls, overloads, templates.
            • CPU jumps directly to address.

        Late Binding (Dynamic Dispatch):
            • Resolved at runtime.
            • Function pointers, virtual functions.
            • CPU reads address from pointer, then jumps.

        Performance:
            • Early: Faster (direct jump).
            • Late: Slightly slower (extra indirection), but more flexible.

    🔹 6 — VIRTUAL TABLE (VTABLE)
    -------------------------------------------------------------
        Implementation Detail (Not in C++ Standard):
            • Lookup table for virtual function resolution.
            • Also called: vtable, virtual method table, dispatch table.

        How It Works:
            1. Each class with virtual functions has vtable (static array).
            2. Each entry = function pointer to most-derived function.
            3. Hidden __vptr member (set when object created).
            4. Points to vtable for that class.

        __vptr:
            • Real pointer member (not like this).
            • Makes objects bigger by one pointer.
            • Inherited by derived classes.

        Virtual Call Steps:
            1. Use __vptr to get vtable.
            2. Index vtable for correct function.
            3. Call function.

        Cost: 3 operations (vs 2 for indirect call, 1 for direct).

    🔹 7 — PURE VIRTUAL & ABSTRACT CLASSES
    -------------------------------------------------------------
        Pure Virtual:
            virtual void func() = 0;  // No body

        Consequences:
            1. Class becomes abstract (can't instantiate).
            2. Derived must define body (or also abstract).

        Why?
            • Base doesn't know implementation.
            • Forces derived to implement.
            • Prevents forgetting to override.

        ✅ Pure virtual can have definition (separate, not inline):
            • Provides default implementation.
            • Derived can call: Base::func().

        ⚠️ Abstract classes with pure virtual need virtual destructor.

        Interface Class:
            • No member variables.
            • All functions pure virtual.
            • Defines functionality contract.

        Vtable for Abstract:
            • Still have vtable (for ctor/dtor).
            • Pure virtual entry: nullptr or __purecall.

    🔹 8 — VIRTUAL BASE CLASSES (DIAMOND PROBLEM)
    -------------------------------------------------------------
        Diamond Problem:
            • Class inherits from two classes with common base.
            • Results in two copies of base.

        Solution (Virtual Inheritance):
            class Scanner : virtual public PoweredDevice {};
            class Printer : virtual public PoweredDevice {};
            class Copier : public Scanner, public Printer {};

        • Only one PoweredDevice object (shared).

        Construction:
            • Most-derived class (Copier) constructs virtual base.
            • Scanner/Printer ctors ignored for PoweredDevice.

        ✅ Virtual bases created before non-virtual bases.

        Overhead:
            • All classes have vtable (even if normally wouldn't).
            • Instances larger by pointer.

    🔹 9 — OBJECT SLICING
    -------------------------------------------------------------
        - Assigning Derived to Base copies only Base portion.
        - "Slices off" Derived portion.

        Issues:
            void func(Base b);  // Pass by value
            func(derived);      // Sliced!

        ✅ Use references to avoid:
            void func(const Base& b);

        Vectors:
            std::vector<Base> v;
            v.push_back(derived);  // Sliced!

        ❌ std::vector<Base&> v;  // Won't compile (refs not assignable)

        Solutions:
            std::vector<Base*> v;  // Pointers
            std::vector<std::reference_wrapper<Base>> v;  // Ref wrappers

        Frankenobject:
            Derived d1, d2;
            Base& b = d2;
            b = d1;  // Only Base portion copied! (d2 = Base of d1 + Derived of d2)

        ⚠️ Hard to prevent.

        ✅ Make base non-copyable (delete copy ctor/assignment) if not meant to instantiate.

    🔹 10 — DYNAMIC CASTING
    -------------------------------------------------------------
        Upcasting: Derived* → Base* (implicit).
        Downcasting: Base* → Derived* (requires cast).

        dynamic_cast:
            Derived* d = dynamic_cast<Derived*>(basePtr);
            if (d) { /* success */ }

        Failure:
            • Returns nullptr if cast invalid.
            • Always check for nullptr!

        Performance Penalty (Runtime Checking):
            • Uses RTTI (Run-Time Type Information).

        Won't Work With:
            • Protected/private inheritance.
            • No virtual functions (no vtable).
            • Some virtual base class cases.

        static_cast (Faster, Unsafe):
            • No runtime checking.
            • "Succeeds" even if invalid → UB.
            ✅ Use if absolutely sure.

        References:
            • Can't return nullptr.
            • Throws std::bad_cast on failure.

        When to Use:
            ✅ Use static_cast unless downcasting (then dynamic_cast).
            ✅ Prefer virtual functions over casting.

        Downcasting vs Virtual:
            Prefer virtual, but downcast when:
                • Can't modify base (standard library).
                • Need derived-specific access.
                • Virtual doesn't make sense for base.

    🔹 11 — PRINTING WITH OPERATOR<<
    -------------------------------------------------------------
        Challenge:
            • Operators are non-member/free functions (can't be virtual).
            • Overload resolution at compile-time (no polymorphism).

        ❌ Can't Make operator<< Virtual:
            • Only members can be virtual.
            • Friends not members.
            • Different params (Base vs Derived) → not override.

        Workaround:
            • Call virtual function from operator<<:
                friend std::ostream& operator<<(std::ostream& out, const Base& b) {
                    return b.print(out);  // Virtual print()
                }

    🔹 12 — BEST PRACTICES
    -------------------------------------------------------------
        ✅ Use virtual for base class polymorphic functions.
        ✅ Use override in derived (not virtual).
        ✅ Make base destructors virtual.
        ✅ Mark class final if not for inheritance.
        ✅ Pass by reference (avoid slicing).
        ✅ Use dynamic_cast for downcasting (check nullptr).
        ✅ Prefer virtual functions over casting.
        ✅ Use virtual inheritance to solve diamond problem.
        ❌ Don't call virtual from constructors/destructors.
        ❌ Don't pass polymorphic objects by value.
        ❌ Don't use static_cast for downcasting (unless certain).
