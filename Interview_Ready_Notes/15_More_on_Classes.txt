=================================================================
📘 C++ MORE ON CLASSES (THIS, HEADERS, NESTED TYPES, DESTRUCTORS, STATIC, FRIENDS)
=================================================================

    🔹 1 — THE HIDDEN THIS POINTER
    -------------------------------------------------------------
        - Every non-static member function has `this` pointer.
        - `this` = const pointer to current object (implicit object).

        const Date* const this;  // For non-const member functions
        const Date* const this;  // For const member functions (const object)

        Uses:
            • Disambiguate members from parameters:
                void set(int x) { this->x = x; }
            • Return *this for method chaining:
                Date& add(int days) { /* logic */; return *this; }

        ⚠️ Returning *this by value creates copy (inefficient).
        ✅ Return *this by reference for chaining.

        Resetting to Default:
            void reset() { *this = Date{}; }  // Assign default-constructed object

    🔹 2 — CLASSES & HEADER FILES
    -------------------------------------------------------------
        - Separate declaration (header) from implementation 
(.cpp).

        Header (.h):
            • Class definition (full, not forward declaration).
            • Inline/trivial functions (access functions).

        Source (.cpp):
            • Non-trivial member function definitions.
            • Scope-qualified: `ClassName::functionName()`

        ODR & Inline:
            • Functions inside class def → implicitly inline.
            • Functions outside class def → NOT inline (define in .cpp).
            • Explicitly `inline` if in header (header-only libraries).

        ✅ Prefer defining non-trivial functions in .cpp (reduces recompilation).

    🔹 3 — NESTED TYPES
    -------------------------------------------------------------
        - Types defined inside class (enums, typedefs, nested classes).

        class Date {
        public:
            enum class Month { jan, feb, ... };  // Nested enum
        };

        Access: `Date::Month::jan`

        ✅ Define at top of class.
        ✅ Use for types closely coupled to the class.

        Nested Classes:
            • No access to outer class's `this`.
            • Can access private members in scope.
            • Used for iterators (std::string::iterator).

    🔹 4 — DESTRUCTORS
    -------------------------------------------------------------
        - Called automatically when object destroyed.
        - Name: `~ClassName()` (no params, no return type).
        - One destructor per class.

        ~Date() { /* cleanup */ }

        • Can call other member functions safely.
        • Implicit destructor generated if none declared.
        • Static/global variables destroyed at program shutdown.

        ⚠️ std::exit() doesn't call destructors (immediate termination).

    🔹 5 — STATIC MEMBERS
    -------------------------------------------------------------
        Static Member Variables:
            • Shared by all objects (not per-instance).
            • Exist even if no objects instantiated.
            • Global variables scoped to class.

        Declaration (inside class):
            static int s_count;

        Definition (outside class, global scope):
            int ClassName::s_count{0};

        ✅ Inline (C++17):
            static inline int s_count{0};  // Define in class

        constexpr (C++17):
            static constexpr int max{100};  // Implicitly inline

        ⚠️ Non-const static members need external definition (unless inline).

        Static Member Functions:
            • No `this` pointer.
            • Can only access static members.
            • Called via class name: `ClassName::function()`.

        ✅ Use for class-level functionality.
        ✅ Prefer inline/constexpr for static members.

    🔹 6 — FRIEND FUNCTIONS
    -------------------------------------------------------------
        - Non-member functions with access to private members.

        class Box {
            friend void print(const Box&);  // Friend declaration
        };

        • Friendship granted by class (not taken).
        • Not affected by access specifiers.
        • Can be friend of multiple classes.

        ⚠️ Changes to class may break friends (tight coupling).
        ✅ Prefer public interface over direct access.
        ✅ Use friends sparingly (when non-member makes semantic sense).

    🔹 7 — FRIEND CLASSES
    -------------------------------------------------------------
        class Storage {
            friend class Display;  // Display can access private members
        };

        • Friendship NOT reciprocal (B friend of A ≠ A friend of B).
        • NOT transitive (A friend of B, B friend of C ≠ A friend of C).
        • NOT inherited (derived classes are NOT friends).

    🔹 8 — REF-QUALIFIERS
    -------------------------------------------------------------
        - Overload member functions based on lvalue/rvalue implicit object.

        std::string& getName() & { return m_name; }        // lvalue
        std::string getName() && { return std::move(m_name); }  // rvalue

        ⚠️ Prevents returning dangling reference from rvalue objects.

        Downsides:
            • Clutter,rare use case.
            • Incompatible with non-ref-qualified overloads.
            • Not idiomatic in C++.

        ✅ Generally not recommended (use results immediately instead).

    🔹 9 — BEST PRACTICES
    -------------------------------------------------------------
        ✅ Return *this by reference for method chaining.
        ✅ Define non-trivial functions in .cpp files.
        ✅ Use static inline/constexpr for static members (C++17+).
        ✅ Use friend functions sparingly (prefer public interface).
        ✅ Define nested types at top of class.
        ✅ Use destructors for cleanup (RAII pattern).
        ❌ Avoid ref-qualifiers unless necessary.
        ❌ Don't call destructors explicitly.
