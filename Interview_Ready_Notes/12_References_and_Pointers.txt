=================================================================
📘 C++ REFERENCES & POINTERS
=================================================================

    🔹 1 — COMPOUND DATA TYPES
    -------------------------------------------------------------
        Fundamental Types: int, double, bool, char, etc.
        
        Compound Types:
            • Functions, Arrays, Pointers, References
            • Enums, Structs, Classes, Unions

    🔹 2 — VALUE CATEGORIES (C++11+)
    -------------------------------------------------------------
        lvalue (locator value):
            • Identifiable object/function with persistent address.
            • Examples: variables, array elements, dereferenced pointers.
            • Subtypes: modifiable lvalue, non-modifiable lvalue (const).

        rvalue (right value):
            • Temporary value (literals, return-by-value).
            • No persistent address (used immediately).
            • Examples: `5`, `x + y`, `func()` (non-ref return).

        Key Rules:
            • lvalue → rvalue conversion (implicit).
            • rvalue ❌ lvalue conversion.
            • Assignment needs modifiable lvalue on left.
            • C-style string literals are lvalues (for backward compatibility).

    🔹 3 — LVALUE REFERENCES
    -------------------------------------------------------------
        Syntax: `int& ref = x;`

        - Alias to existing object (not a separate entity).
        - Must be initialized (cannot be null).
        - Cannot be reseated (bound to one object for life).
        - Independent lifetimes (referent can be destroyed).

        ⚠️ Non-const lvalue ref binds ONLY to modifiable lvalues.
        ⚠️ Dangling reference: Referent destroyed → UB.

    🔹 4 — LVALUE REFERENCES TO CONST
    -------------------------------------------------------------
        Syntax: `const int& ref = x;`

        Binds to:
            ✅ Modifiable lvalues
            ✅ Non-modifiable lvalues (const)
            ✅ Rvalues (temporary objects)

        Lifetime Extension:
            • Const ref to temporary → extends temp's lifetime.
            • Only works for DIRECT binding (not function returns).

        Constexpr References:
            • Can only bind to static duration objects (globals, static locals).
            • Syntax: `constexpr const int& ref = x;`

    🔹 5 — PASS BY REFERENCE
    -------------------------------------------------------------
        Guidelines:
            • Fundamental types, enums → pass by value (cheap to copy).
            • Class types → pass by const reference (expensive to copy).

        std::string_view vs const std::string&:
            ✅ Prefer `std::string_view` (efficient for all string types).
            ❌ Use `const std::string&` only if calling APIs requiring std::string.

    🔹 6 — POINTERS
    -------------------------------------------------------------
        - Stores memory address.
        - Can be null (`nullptr`).
        - Can be reassigned.

        Syntax:
            int* ptr{&x};     // Pointer to x
            int* const cptr{&x}; // Const pointer
            const int* ptr;      // Pointer to const

        ✅ Use `nullptr` for null pointers (not `0` or `NULL`).

    🔹 7 — RETURN BY REFERENCE/ADDRESS
    -------------------------------------------------------------
        ⚠️ Rules:
            ❌ Never return local (non-static) variables by reference.
            ❌ Never return temporaries by reference.
            ✅ OK: Return reference parameters (if they outlive function).
            ✅ OK: Return static locals by reference (use cautiously).

        Lifetime Extension:
            • Direct binding → extends lifetime.
            • Indirect binding (through function) → dangling reference (UB).

        ✅ Prefer return by reference over address (unless `nullptr` needed).

    🔹 8 — IN/OUT PARAMETERS
    -------------------------------------------------------------
        In Parameters:
            • Pass data into function (read-only).
            • Use: pass by value or const reference.

        Out Parameters:
            • Function writes results.
            • Use: non-const reference or pointer.
            • Initial values ignored.

        In-Out Parameters:
            • Function reads AND modifies.

        Modern C++:
            ✅ Prefer returning structs/tuple/pair over out-parameters.
            ❌ Avoid out-parameters (use only if no better option).

            std::pair<int, int> getCoords() { return {10, 20}; }
            auto [x, y] = getCoords(); // C++17 structured bindings

    🔹 9 — TYPE DEDUCTION (AUTO)
    -------------------------------------------------------------
        Rules:
            • Drops references (unless `auto&` or `const auto&`).
            • Drops top-level const (unless `const auto` or `constexpr auto`).
            • Does NOT drop pointers.
            • constexpr never deduced (must be explicit).

        Top-Level vs Low-Level Const:
            • Top-level: `const int x` or `int* const ptr`.
            • Low-level: `const int& ref` or `const int* ptr`.

        Pointers:
            auto ptr{&x};         // auto deduced as int*
            auto* ptr{&x};        // Explicit pointer (preferred for clarity)
            const auto* ptr{&x};  // Pointer to const
            auto* const ptr{&x};  // Const pointer

        ✅ Best Practice: Explicitly reapply const/constexpr/& even if redundant.

    🔹 10 — STD::OPTIONAL (C++17)
    -------------------------------------------------------------
        - Represents optional value (may or may not exist).

        std::optional<int> findValue() {
            if (found) return 42;
            return std::nullopt; // No value
        }

        auto result = findValue();
        if (result.has_value()) { use(*result); }

        ✅ Use Cases:
            • Optional return values (preferred over pointer/sentinel).
            • Optional parameters (when T passed by value).

        ⚠️ For expensive-to-copy types, prefer `const T*` over `std::optional<T>`.

    🔹 11 — BEST PRACTICES
    -------------------------------------------------------------
        ✅ Prefer lvalue references to const over non-const (unless modifying).
        ✅ Use `nullptr` for null pointers.
        ✅ Pass by const reference for class types.
        ✅ Use `std::string_view` instead of `const std::string&`.
        ✅ Return structs/tuples instead of out-parameters.
        ✅ Explicitly apply const/constexpr/& with `auto`.
        ✅ Use `auto*` over `auto` for pointer deduction (clarity).
        ✅ Use `std::optional` for optional return values.
        ❌ Never return local variables by reference.
        ❌ Avoid dangling references.
