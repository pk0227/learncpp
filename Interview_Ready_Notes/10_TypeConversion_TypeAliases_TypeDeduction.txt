=================================================================
📘 C++ TYPE CONVERSION, TYPE ALIASES & TYPE DEDUCTION
=================================================================

    🔹 1 — TYPE CONVERSION BASICS
    -------------------------------------------------------------
        - Conversion produces a TEMPORARY object (doesn't change source).
        - Performed automatically (implicit) or manually (explicit).

        Two Main Categories:
            1. Numeric Promotion (safe, value-preserving)
            2. Numeric Conversion (potentially unsafe, may lose data)

    🔹 2 — NUMERIC PROMOTIONS
    -------------------------------------------------------------
        ✅ Always safe (value-preserving, though signedness may change).

        Integral Promotions:
            bool, char, signed char, unsigned char, short, unsigned short
            → `int` (or `unsigned int` if int can't hold full range)

        Floating Point Promotions:
            float → double

        ⚠️ Widening conversions (char→short, int→long) are NOT promotions.
            They are numeric conversions.

    🔹 3 — NUMERIC CONVERSIONS
    -------------------------------------------------------------
        Three Types:
            1. Value-preserving (safe): int→double (when no precision loss).
            2. Reinterpretive (unsafe): unsigned↔signed (no data loss but different interpretation).
            3. Lossy (unsafe): double→int, int→smaller int (data may be lost).

    🔹 4 — NARROWING CONVERSIONS
    -------------------------------------------------------------
        - Potentially unsafe (destination may not hold all source values).

        +-----------------------------+-------------------------+-------------------------+
        | Conversion                  | Risk                    | Allowed with constexpr? |
        +-----------------------------+-------------------------+-------------------------+
        | Int ← Float                 | Fractional part lost    | ❌                      |
        | Float ← Double              | Precision loss          | ✅ if value fits        |
        | Float ← Int                 | Large int may round     | ✅ if exactly fits      |
        | Smaller Int / Sign Change   | Overflow/reinterpret    | ✅ if value fits        |
        +-----------------------------+-------------------------+-------------------------+

        🛡️ Brace Initialization `{}`:
            • Disallows narrowing conversions (compile-time check).
            • Only checks constexpr values at compile-time.
            • Runtime variables: No compile-time check (may warn).

        ✅ Best Practice:
            • Avoid narrowing conversions.
            • If needed, use `static_cast` for explicit conversion.

        🔍 Type Inspection:
            • Use `typeid(expr).name()` to show deduced type (requires <typeinfo>).

    🔹 5 — C++ CASTS
    -------------------------------------------------------------
        +------------------+----------------------------------------------+-------------+
        | Cast             | Purpose                                      | Safe?       |
        +------------------+----------------------------------------------+-------------+
        | static_cast      | Compile-time conversions (related types)     | ✅ Yes      |
        | dynamic_cast     | Runtime polymorphic conversions              | ✅ Yes      |
        | const_cast       | Add/remove const                             | ⚠️ Risky    |
        | reinterpret_cast | Bit-level reinterpretation                   | ❌ Unsafe   |
        | C-style casts    | Combination (static/const/reinterpret)       | ❌ Unsafe   |
        +------------------+----------------------------------------------+-------------+

        ❌ Avoid: C-style casts, const_cast, reinterpret_cast.

    🔹 6 — STATIC_CAST
    -------------------------------------------------------------
        - Compile-time type checking.
        - Intentionally less powerful than C-style (safer).
        - Uses direct initialization (considers explicit constructors).

        Example:
            int x{10};
            double d = static_cast<double>(x) / 3;  // ✅ explicit conversion

        Benefits:
            ✅ Compile-time errors for invalid conversions.
            ✅ Prevents dangerous conversions (reinterpret, const removal).
            ✅ Clear intent (easy to search/spot).

    🔹 7 — STATIC_CAST vs LIST-INIT TEMPORARY
    -------------------------------------------------------------
        static_cast<int>(x)     vs     int{x}

        Differences:
            1. Narrowing:
                • int{x} disallows narrowing (may fail on 64-bit for int←double).
                • static_cast<int>(x) allows narrowing.

            2. Clarity:
                • static_cast makes conversion intent clearer.

            3. Type names:
                • int{x} works (single-word type).
                • unsigned int{x} invalid (multi-word type).
                • static_cast<unsigned int>(x) works.

        ✅ Prefer `static_cast` for explicit conversions.
        ✅ Use list-init for temporary objects when narrowing protection desired.

    🔹 8 — TYPE DEDUCTION (AUTO)
    -------------------------------------------------------------
        - Compiler deduces type from initializer.

        auto x{5};         // int
        auto y{3.14};      // double
        auto s{"hello"};   // const char* (NOT std::string)
        auto str{"hi"s};   // std::string (with literal suffix)

        🔧 Rules & Limitations:
            ❌ No initializer → error: `auto a;`
            ❌ Empty initializer → error: `auto b{};`
            ❌ void initializer → error: `auto c{foo()};` (if foo returns void)
            ✅ Function calls: `auto x = func();`

        🔒 Const & Type Deduction:
            • auto DROPS const from deduced type.
            • Must explicitly add: `const auto x{5};`
            • constexpr variables are implicitly const (also dropped).

        📝 String Literals:
            auto s{"hello"};    // const char*
            auto s{"hello"s};   // std::string
            auto s{"hello"sv};  // std::string_view

    🔹 9 — AUTO WITH FUNCTIONS
    -------------------------------------------------------------
        Auto Return Types:
            auto func() { return 42; }  // Deduced as int

            ⚠️ Restrictions:
                • All return statements must have same type.
                • Full definition required (forward declaration insufficient).

        Function Parameters:
            ⚠️ Type deduction for parameters:
                void func(auto x) {}  // ❌ Error in C++11/14/17
                                      // ✅ Valid in C++20+ (abbreviated function template)

    🔹 10 — BEST PRACTICES
    -------------------------------------------------------------
        ✅ Prefer `static_cast` for explicit conversions.
        ✅ Use `auto` for complex type names/iterators.
        ✅ Add `const` explicitly when using `auto`.
        ✅ Use literal suffixes (s, sv, f, etc.) with `auto`.
        ✅ Avoid C-style casts.
        ❌ Avoid narrowing conversions (or use `static_cast` if necessary).
        ❌ Avoid `const_cast` and `reinterpret_cast`.
